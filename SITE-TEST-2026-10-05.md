## Issues found

All pre-existing. None caused by the CTA work.

### 1. Both logos are preloaded at full size on every page — HIGH

`src/components/layout/Logo.tsx` renders **both** `logo.webp` (82.8 KB) and
`logo-dark.webp` (81.8 KB), each with `priority` and no `sizes`. The files are
1808×556 but display around 140 px wide. `next/image` therefore emits preload
links at `w=1920` **and** `w=3840` for both.

That is ~165 KB of high-priority image fetches on every page, for two assets of
which only one is ever visible (the other is hidden in CSS), competing directly
with the hero for LCP bandwidth. They account for **72 of the 85** non-lazy
images across the site.

Fix: add `sizes="140px"`, drop `priority` from the hidden variant, and
re-encode the wordmark at display resolution. Likely the single biggest
performance win available.

### 2. Duplicate JSON-LD — MEDIUM

13 of 18 routes emit two `<script type="application/ld+json">` blocks, so
`Organization`, `OnlineBusiness` and `WebSite` each appear 31 times across 18
pages. Valid, but redundant. Source: `src/app/layout.tsx:37`.

### 3. Bundle budget breached, docs stale — MEDIUM

Heaviest route is **131 kB** First Load JS against a stated 120 kB budget.
`README.md:41`, `README.md:51` and `REMAINING-WORK.md:84` all still claim
116 kB.

### 4. `comboMeta` — MEDIUM

`src/lib/seo/metadata.ts:54`, reported previously, still unfixed.

### 5. `backdrop-filter` on `.process-step-card` — LOW

4 occurrences, the last on the site. These cards are static, not sticky, so
they do not cause scroll judder, but they are expensive to composite.

### 6. Dead code — LOW

`ILLUSTRATIVE_IMAGE_NOTE` (`sections.tsx`) is exported and never rendered.
Tailwind also generates `.min-h-[calc(100dvh-3.5rem)]` purely because the
string appears in `README.md:53`; no element uses it.

### Accepted trade-off

CTA photographs are CSS backgrounds, so they have no responsive `srcset` and a
320 px phone receives the same 87–94 KB file as a desktop. Deliberate — a
literal CSS background was requested.
